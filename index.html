The headline

The docs are usually not the bottleneck; permission is. Developer-friendly REST/GraphQL surfaces are common in infrastructure and work tools, but real agent access still depends on account ownership, scopes, admin consent, product tiers and sometimes platform review. Start with self-serve developer platforms; route regulated, ad, commerce and enterprise systems through an explicit access-check queue.

Honesty / scope: this is a useful candidate map, not a fully verified 100-vendor audit. Six official documentation sources were directly fetched and checked for the assertions shown in the audit below. The other rows are evidence-linked research leads and provisional classifications; do not treat absent MCP evidence as proof that no server exists. The full 100-app agent run is not included in this snapshot; run the documented workflow to fetch sources, extract and quote-check candidate claims, and generate a run-specific HTML report. No live deployment or vendor-account testing was performed.

Patterns worth acting on

Dataset-wide read of the candidate classifications below; descriptive, not an independently validated market survey.

1 · OAuth is the default for delegated SaaS

OAuth/token-based access repeats across CRM, support, messaging, marketing and work tools. Personal API keys simplify prototypes, but least-privilege scopes, refresh, tenant install and admin consent are the production work.

2 · “Free credentials” ≠ usable production access

Many platforms let a developer create an app or sandbox. Customer data access can still require a paid subscription, workspace admin, business verification, API review, advertiser/account eligibility or partner approval.

3 · Access friction is the common blocker

Not missing HTTP endpoints: it is obtaining the right customer tenant, scopes, plan, approval, data rights, or stable public API. The hardest candidates also expose no supported write interface.

4 · Easy wins: tools built for developers

GitHub, Linear, Sentry, Vercel, Supabase, Notion and similar products expose clear APIs and self-serve credentials. They are strong first integrations, subject to scope checks and safe write design.

5 · Outreach queue: platform-controlled access

Ads, commerce, fintech, enterprise data and proprietary AI/media products deserve early gate checks. Production review, commercial terms, sensitive data and non-public APIs can dominate build effort.

6 · MCP accelerates; it does not certify

An official MCP server can reduce adapter work, but verify publisher, tool coverage, auth handling and write safeguards. Otherwise wrap the documented API. “Not verified” in this pass is intentionally not “does not exist.”

What the research agent does

Small, reproducible evidence-triage loop—not an LLM pretending to have read 100 sites.

01 · Seed100 app registry

Normalizes app, category, candidate auth/access, API shape, blocker and official evidence URL into one searchable matrix.

02 · GatherFetch first-party pages

research-agent.mjs fetches all 100 evidence links with bounded concurrency and captures page excerpts/status/final URLs.

03 · Extract (optional)Source-constrained model

With --research, asks an LLM for structured auth/access/API/MCP candidates and a source quote; exact-quote matching flags unsupported citations.

04 · Human loopReview and decide

Check plan, eligibility, scopes, API coverage and MCP provenance; adjudicate model uncertainty. Prioritize easy wins and route gated cases to outreach.

Human-needed cases: pricing and plan limits change; API review/partner rules can vary by use case and region; public pages may omit tenant-admin requirements; MCP directories do not prove official support. Model output is a candidate, not a verified fact. The 100-page run was not executed for this submission.

What this proves—and does not
  • 6 of 6 checked source-level claims were supported in the pages fetched. This is a tiny, selected, non-random sample, not the accuracy of all rows.
  • Checked claims: docs/API shape, auth method, API surface breadth, and explicitly documented access gate. We did not independently verify every row’s pricing or MCP status.
  • No pre-loop score or post-loop percentage is claimed: no measured 100-row first-pass labels were retained. Inventing “accuracy improved from X to Y” would be misleading.
  • Some guessed URLs returned fetch errors/404s during this run. They remain leads, not verified evidence; rerun the link checker, then repair or replace with canonical vendor docs.
  • Next loop: stratified random sample across all 10 categories; two humans label auth/access/API/MCP independently; adjudicate disagreements; report per-field precision/coverage with denominator and date.
